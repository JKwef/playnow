# Исправление загрузки статусов — 13 ноября 2026

Причина: в рабочем проекте Supabase отсутствовала таблица `public.game_preferences`. Клиентский запрос статусов завершался ошибкой, которая отображалась общим сообщением о подключении.

С явного разрешения пользователя применена существующая миграция `supabase/migrations/20261113094802_game_preferences.sql` через Management API. Ответ применения: HTTP 200. Созданы таблица, политики RLS для своего аккаунта и функция `set_game_preference`. Код приложения не изменялся.

Проверка через настоящие авторизованные API-сессии временных тестовых аккаунтов:

- Запрос приложения с выборкой `appid, progress_status, excluded`, фильтром пользователя, сортировкой и лимитом успешно возвращает пустой список до первой отметки.
- Обычный авторизованный клиент сохраняет `playing` через `set_game_preference`; повторный запрос возвращает этот статус.
- Изменение `excluded` сохраняет предыдущий статус.
- Второй аккаунт не видит данные первого; анонимное чтение отклоняется.
- Тестовые аккаунты, игры, профили и статусы удалены; отсутствие тестовых строк проверено.

Проверены наличие таблицы, колонок и четырёх политик RLS. Security advisors не сообщил проблем для новой таблицы; есть отдельное предупреждение `auth_leaked_password_protection`, не связанное с этой ошибкой. Настройки Auth не менялись.

Lint и TypeScript приложения и тестов прошли. Проверка интерфейса в реальной пользовательской сессии после исправления не выполнялась: подтверждён успешный запрос через Data API с обычными пользовательскими правами.
