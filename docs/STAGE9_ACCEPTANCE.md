# Этап 9 Стабилизация перед приёмкой Android и iOS

Этап определён владельцем проекта 13 ноября 2026 года: стабилизация и подготовка
к мобильной приёмке. Подготовка исходников выполнена; допуск к выпуску требует
подписанных сборок, проверки сервера и физических устройств.

## Исправления

- Expo обновлён в пределах SDK 58 до совместимого patch-релиза; связанные пакеты
  выровнены через `expo install --fix`. Добавлены рекомендованные config plugins
  SecureStore, StatusBar и WebBrowser. Биометрия не используется, разрешение Face ID
  плагином не добавляется. Генерируемые `android/` и `ios/` не редактировались.
- На узком экране и при системном шрифте больше 1,2 карточки библиотеки получают
  переменную высоту, более компактную обложку и полный текст. FlatList измеряет
  такие строки; для обычного размера сохранён `getItemLayout`.
- При высоте окна меньше 600 dp либо системном шрифте больше 1,3 основное действие
  входит в прокрутку. Оно не забирает всю доступную высоту в ландшафте. На обычном
  телефоне действие остаётся закреплённым.
- Общий ScrollView учитывает клавиатурные отступы iOS. На Android сохраняется
  режим изменения размера окна `resize`. В ручном добавлении выбранный жанр
  отмечен галочкой и ARIA-состоянием; текст Steam-действия уточнён.
- Preview-профиль EAS явно предназначен для физического iOS-устройства и APK
  Android. Добавлена проверка итогового публичного конфига и профилей; CI дополнен
  проверкой совместимости SDK и экспортом всех трёх платформ.

Обновление native-пакетов и плагинов требует новой бинарной сборки. Старая
установленная сборка не подтверждает приёмку этих изменений.

## Воспроизведение подготовки

```powershell
npm ci
npm run validate
npx expo install --check
npx expo-doctor
npm run check:mobile-config
npm run export:acceptance
npm run test:web:stage9
```

Для браузерной проверки нужен доступный Playwright/Chromium или Edge;
настройка `PLAYWRIGHT_MODULE` и `PLAYWRIGHT_CHANNEL` описана в
[инструкции](research/STAGE7_WEB_SMOKE.md). Она использует синтетические аккаунты
и подменяет внешние API. Артефакты лежат в `.tools/stage9-qa`, экспорт —
в `.tools/stage9-export`. Проверка не обращается к настоящим Steam-аккаунтам.

`check:mobile-config` читает результат `expo config --type public --json`:
проверяет callback-схему, идентификаторы приложения, HTTPS-адреса, публичный
тип клиентского ключа и разрешённые поля `extra`. Значения ключей не печатает.
Проверка не доказывает действительность ключа, RLS или доступность сервера.

## Подписанные сборки для физических устройств

В текущем конфиге нет `extra.eas.projectId`. Владелец Expo-проекта должен
выбрать существующий либо создать нужный проект и настроить учётные данные
подписи. Конкретный project ID нельзя подставлять произвольно.

```powershell
npx eas-cli@latest login
npx eas-cli@latest init
npm run check:mobile-config -- --require-eas-project
# До iOS-сборки зарегистрировать тестовые устройства в выбранном проекте:
npx eas-cli@latest device:create
npx eas-cli@latest build --platform android --profile preview
npx eas-cli@latest build --platform ios --profile preview
```

Облачные сборки в рамках подготовки не запускались. Для физического iOS
требуются доступ к Apple Developer и профиль с зарегистрированными устройствами.
Для Android устанавливается APK из результата preview-сборки. На iOS устанавливается
подписанная internal-сборка по ссылке EAS на зарегистрированное устройство.
Схема internal distribution описана в [документации Expo](https://docs.expo.dev/build/internal-distribution/).

После установки записать EAS build ID, версию, commit и состав незакоммиченных
изменений, модель, ОС и окружение сервера. Проверять именно эту бинарную сборку,
а не ранее установленный APK, веб-превью или Expo Go.

## Передача на физическую приёмку

Базовый набор — [матрица D01–D18](research/STAGE7_DEVICE_CHECKLIST.md).
Дополнительно обязательно пройти:

| Условие                                    | Проверка                                                                                                            |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| 320/390 dp, шрифт 1,6–2×, обе темы         | Длинные названия и жанры библиотеки читаются; строки и нажатия совпадают при прокрутке большой библиотеки           |
| Ландшафт и низкое окно                     | Главное действие достижимо прокруткой, остаётся место для выбора контекста                                          |
| Клавиатура открыта                         | Поля поиска и ручного добавления доступны, до кнопки сохранения можно дойти, закрытие клавиатуры не сбрасывает ввод |
| VoiceOver/TalkBack                         | Названия, выбранный режим/жанр, ошибки и кнопки озвучиваются, фокус не теряется при прокрутке                       |
| Перезапуск и возврат из фона/Steam         | Восстанавливаются сессия, принятый выбор и история; внешнее открытие не считается запуском игры                     |
| Аккаунты A/B и удаление тестового аккаунта | Не смешиваются история/кэш/статусы; удаление подтверждено на сервере, локальные данные очищены, тема сохранена      |

Результаты писать в копию матрицы со свидетельствами и кодами ошибок.
Браузерная имитация увеличения текста не заменяет системный масштаб на телефоне.
Поведение платформенной клавиатуры и доступность требуют реальных устройств.

а не разрешение на публикацию.
