# План исправлений PlayNow — нарезка по тредам

Документ составлен по результатам проверки рабочей среды `D:\playnow`
(Windows 10 22H2, PowerShell 5.1, Node 24.15.0, npm 11.12.1, ветка `main`).
Каждый раздел самодостаточен: его можно открыть в отдельной сессии как задачу,
не перечитывая остальные.

Ориентир по состоянию на момент составления:

| Проверка                 | Результат                                           |
| ------------------------ | --------------------------------------------------- |
| `npx tsc --noEmit`       | проходит, 0 ошибок                                  |
| `npx eslint .`           | 4730 ошибок `Delete ␍` (prettier/prettier)          |
| `npx prettier --check .` | проблемы в 107 файлах                               |
| `git`                    | не установлен и не в PATH, хотя каталог `.git` есть |
| `deno` / `supabase` CLI  | нет                                                 |
| Jest / Detox             | нет в `node_modules`, каталоги `tests/*` пустые     |
| `.env`                   | нет (используются значения из `app.json → extra`)   |

Причина массового падения линта одна: **весь репозиторий лежит с переводами
строк CRLF**, а `.editorconfig` и `.prettierrc.json` требуют `lf`.
188 текстовых файлов содержат CR. Это не косметика: без исправления
`npm run validate` не проходит никогда, а значит не проходит и любой CI.

                    ├─► T3 (тесты)
                    └─► T4 (Edge Functions)
T5 (.env и запуск) ─┬─► T6 (зависимости / expo-doctor)
T2 ─────────────────┴─► T7 (CI)

T1 нужно сделать первым: он снимает 4730 ошибок и делает осмысленными T2/T7.
T5, T6 и T4 независимы и могут идти параллельно после T1.

## T1. Нормализовать переводы строк в LF

**Приоритет:** блокирующий. **Зависимости:** нет.

**Проблема.** Все текстовые файлы (`.ts`, `.tsx`, `.js`, `.json`, `.md`, конфиги)
сохранены с CRLF. Prettier настроен на `endOfLine: "lf"`, ESLint подключает
`eslint-plugin-prettier/recommended`, поэтому каждая строка каждого файла — ошибка.

**Шаги.**

1. Добавить `.gitattributes` в корень:
   ```
   * text=auto eol=lf
   *.bat text eol=crlf
   *.cmd text eol=crlf
   *.ps1 text eol=crlf
   ```
2. Перевести файлы в LF. Аккуратный способ — через сам Prettier:
   `npx prettier --write .` (он перезапишет 107 контролируемых файлов).
   Остальные (`.gitignore`, `.editorconfig`, `.gitattributes`, файлы вне
   `prettier`-скоупа) — отдельно, скриптом с явным списком расширений.
3. Проверить, что в файлах не осталось CR: `Select-String -Pattern "`r"`.
4. Перезапустить проверки.

**Критерий готовности.** `npm run validate` завершается с кодом 0;
`npx prettier --check .` — «All matched files use Prettier code style»;
в репозитории нет файлов с CR (кроме перечисленных в `.gitattributes` как
`eol=crlf`).

**Важно.** Правки меняют только переводы строк — логика не затрагивается,
но диф будет на весь репозиторий, поэтому делать это нужно до start работы
над фичами и отдельным коммитом.

## T2. Git: установка и корректная работа с репозиторием

**Приоритет:** высокий. **Зависимости:** T1 (иначе первый коммит зафиксирует
CRLF и всё вернётся).

**Проблема.** Каталог `.git` есть (ветка `main`, remote
`https://github.com/JKwef/playnow.git`), но исполняемого `git` нет ни в PATH,
ни в стандартных путях установки. Нельзя посмотреть историю, статус, сделать
коммит.

**Шаги.**

1. Установить Git for Windows (winget: `winget install --id Git.Git -e`),
   перезапустить терминал, проверить `git --version`.
2. Проверить целостность репозитория: `git status`, `git log --oneline -5`,
   `git remote -v`; при ошибках — `git fsck`.
3. Настроить, чтобы CRLF не вернулся: `git config --global core.autocrlf false`
   (плюс `.gitattributes` из T1).
4. Сделать первый коммит с нормализованными переводами строк, отдельно от
   любых функциональных правок.

**Критерий готовности.** `git status` показывает чистое дерево после коммита,
`git log` читается, push в `origin/main` проходит.

## T3. Тестовая инфраструктура (Jest + React Native Testing Library)

**Приоритет:** средний. **Зависимости:** T1.

**Проблема.** README обещает `tests/unit (Jest)` и `tests/e2e (Detox)`, но в
`devDependencies` нет ни `jest`, ни `@testing-library/react-native`, ни `detox`;
каталоги содержат только `.gitkeep`. Скрипта `test` в `package.json` нет.

**Шаги.**

1. `npx expo install jest-expo jest @types/jest` — версии подбирает Expo,
   вручную в `package.json` не вписывать.
2. `npx expo install --dev @testing-library/react-native`
   (по документации Expo для SDK 58 — проверить на
   `https://docs.expo.dev/versions/v58.0.0/`).
3. Добавить в `package.json`: `"test": "jest --watchAll"`,
   `"test:ci": "jest --ci"` и блок `jest` с `preset: "jest-expo"`.
4. Написать первые тесты на чистые утилиты без нативной зависимости:
   `src/shared/utils/format.ts`, `validation.ts`, `random.ts`,
   `src/features/backlog/utils/filterGames.ts`,
   `src/features/picker/utils/pickGame.ts`.
5. Detox/e2e — отдельная задача, не в этом треде: требует сборки приложения
   и эмулятора.

**Критерий готовности.** `npm test -- --ci` проходит, покрыты ключевые
утилиты выбора игры и фильтрации; `npm run validate` по-прежнему зелёный.

## T4. Проверки для Supabase Edge Functions (Deno)

**Приоритет:** средний. **Зависимости:** T1.

**Проблема.** `supabase/functions/**` исключён из `tsconfig.json` и из ESLint
(`ignores: ['supabase/functions/*']`), а Deno и Supabase CLI не установлены.
Код трёх функций (`steam-auth`, `steam-library`, `rawg-enrich`) и их тесты
(`*.test.ts`) сейчас не проверяются ничем.

**Шаги.**

1. Установить Deno (`winget install --id DenoLand.Deno`) либо Supabase CLI.
2. Прогнать `deno check` по каждому `index.ts` и `deno test` по `*.test.ts`
   в `supabase/functions/`.
3. Решить, как это жить будет в проекте: отдельный npm-скрипт
   (`"check:functions": "deno check supabase/functions/*/index.ts"`)
   или отдельный CI-job (см. T7).
4. Проверить, что `_shared/*` импортируется без дублей и что секреты
   (`STEAM_API_KEY`, `RAWG_API_KEY`) читаются только из окружения,
   а не из бандла.

**Критерий готовности.** Все тесты функций проходят локально, тип-чек функций
запускается одной командой и описан в README.

## T5. Локальное окружение: `.env` и запуск приложения

**Приоритет:** средний. **Зависимости:** T1 (желательно).

**Проблема.** `.env` отсутствует. Приложение при этом работоспособно: `app.config.ts`
подставляет публичные значения из `app.json → extra`. Но непонятно, к какому
проекту Supabase идёт подключение в каждой сессии, и нет примера для второго
окружения.

**Шаги.**

1. Создать `.env` из `.env.example` **только если** нужен отдельный проект
   Supabase; иначе зафиксировать в README, что значения по умолчанию берутся
   из `extra`.
2. Проверить запуск: `npx expo start`, вход через Steam, загрузка бэклога.
3. Проверить web-профиль (`npx expo start --web`) — он быстрее всего ловит
   ошибки импортов и `window`-зависимостей.

**Критерий готовности.** Приложение стартует, логин и список игр работают
на реальном проекте; в README описано, откуда берутся ключи.

## T6. Зависимости и `expo-doctor`

**Приоритет:** средний. **Зависимости:** нет (можно параллельно с T1).

**Проблема.** `npx expo-doctor` в этой сессии не запускался. Пакеты в
`package.json` выглядят согласованными с SDK 58 (`expo ~58.0.22`,
`react-native 0.88.1`, `react 19.3.0`), но проверены только глазами.

**Шаги.**

1. `npx expo-doctor` — разобрать каждое предупреждение.
2. Если есть расхождения версий — `npx expo install --fix` (не править
   версии руками).
3. Убедиться, что нет лишних зависимостей (например, `expo-router` не нужен —
   проект на React Navigation, это требование `AGENTS.md`).
4. Проверить `npx expo config --type public` — что `extra` содержит только
   публичные значения.

**Критерий готовности.** `npx expo-doctor` без ошибок; список зависимостей
соответствует SDK; в `extra` нет секретов.

## T7. CI: проверки на каждый PR

**Приоритет:** низкий/после T1–T3. **Зависимости:** T1, T2, T3.

**Проблема.** Сейчас нет ничего, что мешает закоммитить код, не проходящий
`validate`. GitHub-репозиторий есть (`JKwef/playnow`), Actions не настроены.

**Шаги.**

1. `.github/workflows/ci.yml`: Node 24, `npm ci`,
   `npm run typecheck`, `npm run lint`, `npm run format:check`, `npm test -- --ci`.
2. Отдельный job для Edge Functions (Deno) после T4.
3. Включить защиту ветки `main`: merge только при зелёном CI.

**Критерий готовности.** PR с намеренно сломанным форматированием падает
в CI; PR с корректным кодом — зелёный.
