# Quaeso

Мобильное приложение, которое подбирает игру из вашего Steam-бэклога под выбранный режим и жанровый контекст.

В режиме «Новое» сначала предлагаются игры со статусом «Не начинал», затем — без статуса и с нулевым временем. В «Продолжить» сначала идут отмеченные «Играю», затем — без статуса и с ненулевым временем. Пройденные, исключённые и отложенные игры не участвуют. Режим и контекст сохраняются для аккаунта на устройстве.

Подбор объясняет применённые критерии и не повторяет игры до конца серии. Новый круг начинается по явному действию. «Головоломки и аркады» — жанровый контекст без обещания длительности сессии. При неполных метаданных можно явно отключить фильтр жанров, сохранив режим и исключения.

«Выбираю эту игру» сохраняет принятое решение на текущем устройстве. Последний выбор, его режим, контекст и время видны на главном экране после перезапуска; новый подбор его не заменяет. Принятие можно отменить, вернув предыдущий выбор. В настройках можно включить синхронизацию выбора и сроков откладывания между устройствами одного аккаунта; по умолчанию она выключена. На телефоне доступны страница Steam и копирование ссылки, в браузере на ПК — также передача ссылки клиенту Steam. Открытие ссылки не подтверждает запуск игры и не запускает удалённый компьютер. Подробнее: [приёмка этапа 5](docs/STAGE5_ACCEPTANCE.md) и [синхронизация этапа 12](docs/STAGE12_ACCEPTANCE.md).

> Полная инструкция появится на этапе 14. Ниже то, что уже работает.

До входа доступно демо на явно обозначенной примерной библиотеке. После входа
разделы «Подбор / Библиотека / Настройки» открываются во вкладках с сохранением
поиска и выбранного режима. Подробнее: [реализация и приёмка этапа 6](docs/STAGE6_ACCEPTANCE.md).

Для проверки полезности подготовлен [комплект этапа 7](docs/STAGE7_REPORT.md):
протокол сессий, бланки замеров, матрица устройств и повторяемая веб-проверка.
Реальные пользовательские сессии ещё не проведены.

На главном экране доступна история 20 последних рекомендаций на устройстве:
сохранённую игру можно открыть и явно выбрать заново, если она по-прежнему
подходит под сохранённые условия. История разделена по аккаунтам; её очистка сохраняет принятый
выбор. Подробнее: [локальная история этапа 8](docs/STAGE8_ACCEPTANCE.md).

Для мобильной приёмки подготовлены исправления крупного шрифта и клавиатуры,
проверка конфигурации и экспорт всех платформ. Команды установки и открытые
условия выпуска: [подготовка этапа 9](docs/STAGE9_ACCEPTANCE.md).

После перехода к другой рекомендации можно необязательно указать причину отказа
для предыдущей игры. Причина сохраняется только в локальной истории, удаляется
отдельно и не меняет статусы или подбор. Подробнее: [этап 10](docs/STAGE10_ACCEPTANCE.md).

В карточке и результате можно вручную отметить установку на своём игровом
компьютере. Фильтр «Только отмеченные установленными» хранится для аккаунта
на устройстве и сохраняет все исключения; автоматической проверки Steam нет.
Подробнее: [этап 11](docs/STAGE11_ACCEPTANCE.md).

Текущее состояние, найденные риски и приоритеты разработки:
[технический аудит](docs/TECHNICAL_AUDIT.md).

## Быстрый старт

Требуется Node.js 24 и npm. В Windows-среде Codex, где Node уже доступен,
а npm отсутствует в PATH, выполните в корне проекта:

```powershell
. ./scripts/dev-env.ps1
npm.cmd ci
npm.cmd run validate
```

Скрипт настраивает только текущий PowerShell и при необходимости загружает
npm 11.6.2 в игнорируемую `.tools/` с проверкой SHA-256. Для первого запуска
нужен доступ к registry.npmjs.org. В новой консоли повторите dot-source.

Если `node --version` работает, но сетевые команды в Codex получают `EACCES`,
проверьте разрешения сети sandbox. В проверенной среде localhost работал,
а HTTPS к npm registry возвращал `EACCES` внутри sandbox и `200` с одобренным
сетевым доступом. Это не блокировка запуска Node.js. Для разовых загрузок
достаточно одобрения конкретной команды; постоянные сетевые разрешения задаются
в конфигурации Codex с учётом управляемых политик.
См. [официальную документацию о сетевых разрешениях](https://learn.chatgpt.com/docs/agent-approvals-security#network-access).

```bash
npm ci
npx expo start
```

`.env` для запуска **не обязателен**. Публичная конфигурация проекта Supabase уже лежит в `app.json` → `extra`:

- `extra.supabaseUrl` — URL проекта Supabase;
- `extra.supabaseAnonKey` — publishable/anon key (публичный по своей природе: доступ к данным ограничивает RLS);
- `extra.privacyPolicyUrl` — ссылка на политику конфиденциальности для экрана настроек.

`app.config.ts` только прокидывает эти значения в итоговый `extra`, поэтому приложение стартует «из коробки», без локального env-файла.

`.env` нужен, только если вы подключаете приложение к **другому** проекту Supabase:

```bash
cp .env.example .env   # и заполните значения
```

Переменные окружения и куда каждая попадает:

- `SUPABASE_URL` — URL проекта Supabase. Переопределяет `extra.supabaseUrl` и попадает в клиентский бандл.
- `SUPABASE_ANON_KEY` — anon/publishable key. Переопределяет `extra.supabaseAnonKey` и попадает в клиентский бандл.
- `STEAM_API_KEY`, `RAWG_API_KEY` — **серверные** секреты. В приложение и в `extra` не попадают: они живут только в секретах Edge Functions (`npx supabase secrets set …`, см. [docs/SETUP_KEYS.md](docs/SETUP_KEYS.md)).
- `service_role` / secret key Supabase не кладите ни в `.env`, ни в приложение: он обходит RLS и даёт полный доступ к базе.

## Проверки

```bash
npm run validate    # typecheck + eslint + prettier --check + Jest
```

- `npx expo config --type public` печатает итоговый конфиг. В `extra` должны быть только `supabaseUrl`, `supabaseAnonKey` и `privacyPolicyUrl`; ключей `STEAM_API_KEY`/`RAWG_API_KEY` там быть не должно.
- `npx expo export --platform web` проверяет, что приложение собирается без устройства. Каталог `dist/` в `.gitignore`.

Файлы репозитория хранятся в LF: так задано в `.gitattributes` (`* text=auto eol=lf`, CRLF оставлен только для `*.bat`, `*.cmd`, `*.ps1`) и в Prettier (`endOfLine: "lf"`). На Windows не включайте `core.autocrlf=true` и не коммитьте CRLF — расхождение поймает `npm run format:check` (входит в `npm run validate`).

## Скрипты

| Команда                           | Что делает                             |
| --------------------------------- | -------------------------------------- |
| `npm start`                       | dev-сервер Expo                        |
| `npm run typecheck`               | проверка типов (TypeScript strict)     |
| `npm run lint` / `lint:fix`       | ESLint (+ Prettier как правило)        |
| `npm run format` / `format:check` | Prettier                               |
| `npm run validate`                | typecheck + lint + format:check + Jest |

## Структура

```
src/
  features/      auth, backlog, picker, settings (экраны, компоненты, хуки, сервисы, типы)
  shared/        components, hooks, services, utils, types, constants, config
  navigation/    навигаторы React Navigation
supabase/        миграции и Edge Functions (прокси к Steam/RAWG)
tests/           unit (Jest); e2e пока содержит только .gitkeep
```

Импорты из `src` пишутся через алиас `@/`, например `import { colors } from '@/shared/constants'`.
